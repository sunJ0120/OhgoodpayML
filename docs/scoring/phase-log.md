### 데이터 결정 기록 (Phase 8 최종 문서로 옮긴다)

1. **상환 상태 정규화: `-2, -1, 0 → 0`, `k ≥ 1 → k`** (지시서 기본 규칙, 가정)
   - 근거: 세 값의 부실비가 12.8~16.8%로 서로 비슷하고 연체(1 이상)와 확연히 갈린다
   - 관찰: **-1(정상 납부)이 0보다 부실비가 약 4%p 높다.** 0은 문서에 없는 값이라 최소납부 후 이월일 가능성이 있는데, 그렇다면 0이 더 위험해야 한다. 이 데이터에서는 반대라서 의미를 확정할 수 없다
2. **PAY_2~PAY_6에는 `1` 값이 거의 없다** (PAY_2 28건, PAY_3 4건, PAY_5·PAY_6 0건). PAY_0에는 3,688건이다. PAY_0의 영향이 크게 나올 수 있다
3. **음수 청구액**: `avg_billed_amount_6m`은 음수를 포함한 평균, `active_months`는 `BILL_AMT > 0`인 달만 센다 (지시서 정의 그대로). Phase 2 구간표를 보고 처리를 바꿀지 정한다
4. **컬럼명 복원**: ucimlrepo는 `X1..X23`만 준다. `variables.description`으로 원래 이름을 복원하고, 모르는 설명이 나오면 예외를 낸다
5. **제외 컬럼 5개**: `SEX`, `EDUCATION`, `MARRIAGE`, `AGE`, `LIMIT_BAL`. 변수 5개를 만드는 단계에서 구조적으로 빠지고, `validate_training_frame`이 한 번 더 막는다

### 구현 규칙
- **구간 경계**: `lower < x <= upper`, `None`은 무한대, 학습 범위 밖 값은 가장 바깥 구간
- **초기 구간**: 연속 변수는 분위수 5구간(관측된 값만 경계로 사용), 이산 변수는 값 기준
- **방향**: 데이터에서 자동 결정. 두 방향으로 병합해 구간이 더 많이 남는 쪽을 택하고, 같으면 x와 라벨의 순위 상관 부호를 따른다
- **단조 병합**: 부실비가 엄격히 단조가 될 때까지 위반한 인접 구간을 합친다. 부실비가 같은 이웃도 합친다. 예: `[0.10, 0.25, 0.20, 0.40]` → `[0.10, 0.225, 0.40]`
- **최소 구간 크기**: 전체의 5% 미만인 구간을 부실비가 가장 가까운 이웃에 합친다. 단조 병합 뒤에 해도 단조가 유지된다
- **누수 방지**: 구간과 WoE는 학습 데이터로만 만들고(`fit_woe_tables`), 검증 데이터에는 그 구간표를 적용만 한다(`apply_woe`, 라벨을 쓰지 않음)
- **분할**: 층화 70/30, seed=42. 학습 21,000명(부실비 22.12%), 검증 9,000명(부실비 22.12%)

### 판단이 필요한 것
1. **`max_delinquency_months`와 `on_time_ratio`는 사실상 같은 정보다.** 두 변수의 최우량 구간이 정확히 같은 13,934명(정상 12,316, 부실 1,618)이다. `on_time_ratio`가 1.0이면 6개월 모두 연체가 없다는 뜻이라 `max_delinquency_months = 0`과 동치이기 때문이다. Phase 3에서 두 WoE가 강하게 겹쳐 계수 부호가 뒤집히거나 불안정해질 수 있다. 둘 다 둘지, 하나를 뺄지 결정이 필요하다
2. **`active_months`**: 가설과 반대이고 구분력도 약하다(구간 2개, 부실비 차이 2.2%p). 지시서 원칙대로 억지로 맞추지 않고 보고한다. 유지, 제외, 정의 변경 중 하나를 정해야 한다
3. **`avg_billed_amount_6m`**: 구간 2·3(WoE +0.0244, +0.0279)이 거의 같아 사실상 구분력이 약하다. 음수 청구액이 가장 낮은 구간에 섞여 있다. 음수 청구액 처리를 바꿀지(0으로 보거나 별도 구간) 함께 판단이 필요하다

> Phase 3 시작 시 위 세 건에 별도 답이 없어, 5개 변수를 모두 유지한 채 진행했다 (Phase 3에서 계수 부호를 보고 판단하기로 한 안).

| 확인하는 것 | 방법 |
|---|---|
| 알려진 관계에서 β가 모두 음수이고 참값에 가깝다 | 합성 데이터 (β = -0.9, -0.5, 절편 -1.2), 허용 오차 0.12 |

| β가 0 이상이면 그 변수를 지목하는 예외 | `CoefficientSignError`, 변수 이름을 메시지와 `variables`에 담음 |
| 입력 검증 | 변수 없음, 길이 불일치, WoE 결측, 라벨이 0/1이 아님 |

3. **`active_months`**: 데이터 방향이 가설과 반대(Phase 2)인데 β는 음수로 통과했다. 부호 검사가 WoE 방향을 이미 안전한 쪽으로 맞춰 주기 때문이다. 부호 검사 통과가 가설 일치를 뜻하지는 않는다는 점에 주의가 필요하다

### 구현 규칙
- 카드 파일은 `lower < x <= upper`, `null`은 무한대 규칙을 쓴다
- 알 수 없는 최상위 필드는 거부한다. 선택 필드는 `created_at`, `bands_status`뿐이다
- 로드 시 모든 `beta`는 음수여야 한다. `bad_rate`는 0~1, `woe`와 `points`는 유한한 숫자여야 한다
- `bands`는 `min_score`가 큰 등급부터 엄격히 내림차순이고 이름이 겹치지 않아야 한다
- 내보내기는 런타임과 같은 검증을 먼저 통과시키고, 실패하면 **파일을 만들지 않는다**. NaN과 무한대는 JSON에 쓰지 않는다
- 배점과 WoE는 **반올림 없이 전체 정밀도**로 저장한다 (Phase 4에서 제안한 소수 유지안). 사용자에게 보여 줄 최종 점수의 반올림은 Phase 6에서 정한다

- `model_version` = `uci-validation-v1`, `purpose` = `pipeline-validation`, `currency` = `TWD`

|---|---:|---:|---:|---:|---:|
| 최소 점수 | 550 | 544 | 537 | 502 | 467 |

### 판단이 필요한 것
1. **임시 등급 경계는 상위 구간이 매우 좁다.** A·B·C가 550, 544, 537로 13점 안에 몰려 있다. 변수 5개의 구간 조합이 이산적이라 상위 점수대에 같은 점수가 많이 몰리기 때문으로 보인다(추정). 5분위로 자르는 방식은 초안일 뿐이며, 실제 경계는 Phase 7 점수 구간별 부실비 표를 보고 사람이 정해야 한다
2. **로더는 배점이 `β`, `WoE`, 절편과 일관된지 검증하지 않는다.** 내보내기 쪽에서는 공식과 일치함을 테스트로 확인했지만, 사람이 카드 파일의 배점만 직접 고치면 로더가 잡지 못한다. 로드 시 검증을 추가하려면 허용 오차를 정해야 하고, 이후 정수 배점으로 반올림하는 카드(예: 지시서 예시)를 쓰려면 이 검증과 충돌한다. 지금은 넣지 않았다
3. **`created_at`은 선택 필드로 두었다.** 지시서의 필수 필드 목록에 없어서다. 운영 카드에서 필수로 할지 정해야 한다

| 파일 | 내용 |

기존 `ohgood_score.py`와 `/score`는 건드리지 않았다. 런타임 패키지(`app.domain.scoring.scorecard`)를 import해도 pandas, numpy, statsmodels, `training`은 로드되지 않는다.

### 구현 규칙
- **API**: `score_customer(card, features, input_currency=...)`. `input_currency`는 필수 인자이고 카드 통화와 다르면 채점 전에 `CurrencyMismatchError`
- **구간**: `lower < x <= upper`, 이분 탐색(`bisect_left`)
- **최종 점수**: 소수 배점을 그대로 합산한 뒤 마지막에 한 번 반올림. 0.5는 올림 (파이썬 `round()`는 짝수로 반올림해서 쓰지 않음). 합산 전 값은 `raw_score`로 함께 돌려준다
- **등급**: 반올림된 점수가 처음으로 `min_score` 이상인 등급. 모든 경계 아래면 가장 낮은 등급
- **감점 사유**: `points_lost = 해당 변수 최고 배점 − 실제 배점`, 상위 3개, 0 제외
- **입력 검증**: 누락(`MissingFeatureError`), 카드에 없는 변수(`UnknownFeatureError`), 유한한 숫자가 아닌 값(`InvalidFeatureError`: None, NaN, inf, 문자열, bool, 리스트)

### 결과: 실제 UCI 카드로 채점한 예

입력: 최대 연체 2개월, 정시상환 비율 0.5, 6개월 납부액 3,000, 평균 청구액 50,000, 청구 있는 달 6개월

- 점수 469 (합산 468.70), 등급 E
- 감점 사유 상위 3개: `on_time_ratio` (58.9점 손실), `paid_amount_6m` (23.4점), `max_delinquency_months` (6.9점)

### 판단이 필요한 것
1. **카드에 없는 변수가 입력에 있으면 거부한다.** 지시서에는 "누락 시 예외"만 있었다. Phase 0의 `/score` 입력 검증과 같은 방침으로 정했지만, 호출자가 고객 전체 레코드를 그대로 넘기는 구조라면 오히려 불편하다. 무시하도록 바꿀지 정해야 한다
2. **모든 경계 아래의 점수는 가장 낮은 등급을 준다.** 지시서에 정해진 동작이 없어 정한 것이다. 예외로 처리하는 방법도 있다
3. **구간 라벨의 소수점이 길다.** 예: `(31047.166666666668, 71315.5]`. 감점 사유를 사용자에게 보여 주려면 표시용 반올림이 필요하다. 채점 결과에는 영향이 없다
4. **런타임에는 입력 변수를 만드는 코드가 없다.** `score_customer`는 이미 계산된 변수 5개(`max_delinquency_months` 등)를 받는다. 변수를 UCI 컬럼에서 만드는 코드는 `training`(pandas)에만 있고, 오굿페이의 실제 결제·상환 이력에서 변수를 만드는 코드는 운영 전환 단계(후속 과제)에서 필요하다

### 변수 정리 미결 건 (Phase 2부터 이어짐)
위 예시에서도 감점 사유 1위가 `on_time_ratio`(58.9점)이고 `max_delinquency_months`는 6.9점이다. 연체 정보가 한 변수에 쏠리는 문제가 채점 결과에서도 그대로 드러난다.

> Phase 7 시작 시 위 4건과 변수 정리 건에 별도 답이 없어, 5개 변수 그대로 두고 진행했다. Phase 6의 입력 거부 · 최저 등급 규칙도 그대로다.

| 확인하는 것 | 방법 |
|---|---|
| 점수를 5구간으로 나눠 구간별 건수와 부실비 계산 | 20명씩 5구간, 부실 수 `[16, 12, 8, 4, 0]` → 부실비 80/60/40/20/0%, 합계 보존 |

| 같은 점수가 몰리면 | 점수 3종류뿐인 데이터에서 5구간 미만으로 나뉘고 한 점수가 두 구간에 걸치지 않음 |
| **"점수가 오를수록 부실비가 내려가는지" 판정** | 단조 `[16,12,8,4,0]` → 단조, 꼬임 `[16,8,12,4,0]` → 비단조(구간 2→3), 같은 값 → 비단조, 계속 상승 → 4곳 위반 |
| 등급별 표 | 런타임과 같은 규칙(경계 점수는 높은 등급, 모든 경계 아래는 가장 낮은 등급), 빈 등급은 부실비 없음 |
| 등급 경계 초안 | 구간 최소 점수를 위에서부터 A, B, … 로. 초안을 적용하면 구간 표와 같은 인원 · 부실비가 나옴 |
| 마크다운 | 표 머리글, 비율 표기, 판정 문구, 위반 위치, "초안" 안내, 카드 등급 표 |
| 입력 검증 | 라벨이 0/1이 아님, 길이 불일치, 점수가 모두 같음 → `ValueError` |

### 해석 (확인한 것과 추정을 구분한다)

- **확인한 것**
  - 학습에 쓰지 않은 데이터에서도 5구간 기준으로 부실비가 단조롭게 내려간다

- **확인하지 않은 것**
  - 단조 판정은 5구간 기준이다. 더 잘게 나눴을 때도 단조인지는 보지 않았다
  - 이 결과는 UCI(대만 카드, 부실비 22.1%)에서만 확인된 것이다. 오굿페이 모집단에서의 성능을 말해 주지 않는다

### 판단이 필요한 것
1. **등급을 몇 개로 나눌지, 경계를 어디에 둘지.** 상위 세 구간의 부실비가 9~12%로 붙어 있어 A·B·C를 따로 두는 것의 근거가 약하다. 예를 들어 상위를 하나로 묶고 하위를 세분하는 방식이 데이터와 더 잘 맞는다. 등급이 한도나 승인에 연결된다면 운영 정책도 함께 봐야 한다
2. **카드의 임시 등급 경계(A 550 / B 544 / C 537 / D 502 / E 467)를 교체할지.** 위 "경계 초안" 표는 다른 값이다. 확정되면 카드를 다시 내보내고 `bands_status`를 `draft`에서 바꿔야 한다. 이번에는 카드 파일을 수정하지 않았다
3. **변수 정리(Phase 2부터 이어진 미결 건)와의 관계.** 상위 구간의 변별력이 낮은 것과 `on_time_ratio` 쏠림이 관련 있는지는 검증하지 않았다. 변수를 바꾸면 구간 · 계수 · 카드가 전부 달라지므로, 변수를 정리한다면 등급 경계는 그 뒤에 정하는 것이 맞다
